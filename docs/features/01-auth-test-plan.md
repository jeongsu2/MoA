> **열린 질문은 모두 추천안으로 확정 (D-34, 2026-10-13).** 빠진 API(A-18, M-06~M-09)는 다음 범위.
> 2026-10-13, 작성: qa, 입력: [01-auth.md](01-auth.md), [requirements.md](../requirements.md) 8장, [erd-v2.md](../erd/erd-v2.md)

## 0. 공통 규칙
- 종류: **단위** = 서비스, 도메인 로직 (DB 없음). **통합** = MockMvc + Testcontainers MySQL 8.4 (D-33). H2는 쓰지 않는다.
- 동시성 테스트는 `@Transactional` 테스트 롤백을 쓰지 않는다 (다른 스레드가 데이터를 못 봄). 테스트마다 테이블을 비운다.
- 동시성 테스트는 스레드를 `CountDownLatch`로 동시에 출발시키고, 한 번이 아니라 **50번 반복**한다. 한 번이라도 실패하면 버그로 본다.
- "행이 안 생김"은 응답 코드가 아니라 **DB 행 수**로 확인한다.
- CSRF(Q-7 A): 상태를 바꾸는 요청은 `/api/auth/csrf`로 받은 토큰을 붙여 보낸다. 토큰 없는 요청 테스트는 따로 둔다.

## 4. 구현 전에 정할 것 (QA가 본 위험)
- **Q-8 A는 ERD v2에 `users.nickname` 유니크가 없다.** 추천안대로 가면 architect가 v3 제안을 써야 한다. A-11, M-07은 그 결정 후에 확정.
- A-13 길이 값(아이디, 비밀번호, 닉네임 최소와 최대)이 기능 문서에 없다. pm이 숫자를 정해야 테스트 값이 정해진다.
- A-10, A-11: 유니크 위반 예외를 409로 바꾸지 않으면 500이 난다. 앱의 "먼저 조회 후 저장"만으로는 동시 요청을 못 막으므로 DB 예외 처리가 꼭 있어야 한다.
- M-09는 claim 기능이 없어도 테스트 데이터를 직접 넣어 검증한다. 실명 변경과 당첨이 동시에 일어나는 경우는 claim 기능 테스트 계획에서 다룬다.
