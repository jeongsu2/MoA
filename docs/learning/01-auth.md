# 학습 포인트 01. 회원가입과 로그인 (#26)

## 핵심 개념
- **세션 로그인:** 서버가 세션을 만들고 브라우저는 JSESSIONID 쿠키만 들고 다님. 세션을 지우면 바로 로그아웃 (D-16)
- **세션 고정 공격:** 로그인 전 세션 id를 공격자가 심어 두고, 로그인 뒤 그 id로 들어오는 공격. 로그인 순간 `changeSessionId()`로 막음
- **CSRF:** 쿠키가 자동으로 붙는 걸 노려 다른 사이트에서 요청을 보내는 공격. 쿠키에 담은 토큰을 헤더로도 보내게 해서 막음. 로그인 때 토큰도 새로 바꿈
- **DB 유니크가 마지막 방어선:** "먼저 조회 후 저장"은 동시 요청 사이에 틈이 있음. 그래서 바로 저장하고 유니크 위반을 409로 바꿈
- **BCrypt:** 느리게 만든 해시 + 소금(salt). 같은 비밀번호도 매번 다른 해시. 72바이트까지만 써서 비밀번호를 영문, 숫자, 특수문자로 제한함

## 면접 질문 3개
1. 로그인 직후 세션 id를 바꾸는 이유는? (세션 고정 공격)
2. 아이디 중복을 먼저 조회했는데도 동시에 가입하면 왜 500이 날 수 있나요? 어떻게 막았나요? (조회와 저장 사이 틈, DB 유니크 예외를 409로)
3. JWT 대신 세션을 고른 이유와, 계정을 정지했을 때 바로 막히게 한 방법은? (웹앱 하나, 즉시 차단. 요청마다 DB status 확인)
