# 학습 포인트 06. 5분 만료와 차순위 승계 (#31)

## 핵심 개념
- **스케줄러 + 조건부 UPDATE:** `UPDATE claim SET status='EXPIRED' WHERE id=? AND status='WON' AND deadline_at <= ?`. 바뀐 행이 1일 때만 승계. 스케줄러가 겹쳐 돌아도, 입금완료와 동시여도 한쪽만 성공
- **경계 시각:** 입금완료는 `now < deadline`, 만료는 `deadline <= now`. 정확히 5분 0초엔 둘이 겹치지 않음
- **락 순서로 데드락 막기:** 두 사람의 quota를 잡을 땐 항상 user_id 작은 순서. 순서를 빼면 테스트가 실제로 데드락으로 실패
- **READ COMMITTED가 필요한 이유:** 락을 기다리는 사이 커밋된 댓글을 후보로 봐야 함. REPEATABLE READ면 옛 스냅샷이라 못 보고 엉뚱한 사람이 당첨됨. 순서를 고정한 테스트로 증명
- **서버가 늘면:** 스케줄러가 서버마다 돌아도 조건부 UPDATE라 결과는 맞지만 일이 겹침. 그때 ShedLock 또는 `SKIP LOCKED`

## 면접 질문 3개
1. 5분 만료를 스케줄러로 했을 때, 스케줄러가 두 번 돌거나 입금완료와 동시에 오면 어떻게 되나요? (조건부 UPDATE로 한쪽만)
2. 서버를 3대로 늘리면 만료 스케줄러는 어떻게 바꿔야 하나요? (ShedLock, SKIP LOCKED, 결과 정합성은 이미 DB 조건이 지킴)
3. 데드락이 날 수 있는 지점을 어떻게 찾았고 어떻게 막았나요? (락 순서 고정, 순서를 빼서 테스트가 실패하는지 확인)
