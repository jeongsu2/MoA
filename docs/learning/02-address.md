# 학습 포인트 02. My 배송지 관리 (#27)

## 핵심 개념
- **비관적 락 (SELECT ... FOR UPDATE):** 먼저 잡은 트랜잭션이 끝날 때까지 다른 트랜잭션이 같은 행을 못 잡고 기다림
- **대표 행 잠그기:** 새로 추가될 배송지는 아직 행이 없어서 잠글 수 없음. 그래서 그 사람을 대표하는 users 행을 잠가 요청을 한 줄로 세움
- **확인 후 행동(check-then-act) 경합:** "지금 9개니까 추가 OK"를 두 요청이 동시에 판단하면 11개가 됨. 락 없이는 확인과 저장 사이에 틈이 생김
- **IDOR:** 남의 id를 넣어 남의 데이터를 건드리는 공격. 조회 조건에 항상 세션의 userId를 같이 넣고, 남의 것과 없는 것을 같은 404로 응답해 존재 여부도 숨김
- **실험 결과:** 락을 빼고 돌리면 동시 추가는 11개, 동시 기본 변경은 MySQL 데드락으로 500이 남

## 면접 질문 3개
1. 배송지 행이 아니라 회원 행을 잠근 이유는? (아직 없는 행은 잠글 수 없음)
2. 락 없이 "개수 확인 후 저장"을 하면 어떤 일이 생기고, 테스트로 어떻게 증명했나요? (11개, CountDownLatch로 동시 출발)
3. 남의 배송지 요청에 403이 아니라 404를 준 이유는? (존재 여부를 숨김)
