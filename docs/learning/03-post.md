# 학습 포인트 03. 판매 글과 상품 등록 (#28)

## 핵심 개념
- **저장소 인터페이스 (D-17):** ImageStorage 뒤에 로컬 구현을 두면 S3로 바꿀 때 구현 클래스 하나만 바뀜
- **업로드 보안:** 확장자나 Content-Type은 클라이언트가 속일 수 있어서 파일 앞부분 바이트(매직 넘버)로 형식을 봄. 파일 이름은 서버가 UUID로 정해 경로 조작(../)을 막음
- **조건부 UPDATE로 상태 전이:** `UPDATE sale_post SET status='OPEN' WHERE id=? AND status='DRAFT'`. 바뀐 행이 0이면 이미 다른 상태라는 뜻. 동시에 두 번 눌러도 한 번만 바뀜
- **멱등성:** 이미 OPEN인 글을 다시 오픈하면 에러 대신 같은 결과(200)를 줌. 네트워크 재전송에 안전
- **상품 잠금:** 오픈 뒤 상품을 바꾸면 이미 달린 주문 댓글과 어긋나서 막음

## 면접 질문 3개
1. 이미지 형식을 확장자가 아니라 파일 내용으로 확인한 이유는? (확장자 위조)
2. 오픈 API를 수정 API와 따로 두고 조건부 UPDATE로 만든 이유는? (상태 전이를 한 곳에서, 동시 요청에도 한 번만)
3. 로컬 저장으로 시작했을 때 서버를 2대로 늘리면 무슨 문제가 생기고, 어떻게 대비했나요? (파일이 서버마다 흩어짐, 인터페이스로 S3 교체 비용을 낮춤)
