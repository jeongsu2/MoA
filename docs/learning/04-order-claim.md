# 학습 포인트 04. 댓글 주문과 선착순 당첨 (#29)

## 핵심 개념
- **비관적 락으로 줄 세우기 (D-22):** 같은 상품에 동시에 온 정확한 댓글은 상품 행 FOR UPDATE에서 한 줄로 섬. 먼저 잡은 사람이 당첨, 뒤 사람은 RESERVED를 보고 대기 후보가 됨
- **락 순서와 데드락:** 댓글 INSERT의 FK 검사가 상품 행에 공유 락을 먼저 걸면, 두 요청이 공유 락에서 배타 락으로 올리려다 서로 기다림(데드락). 그래서 상품 락을 가장 먼저 잡음. 순서는 항상 product, quota
- **조건부 UPDATE는 마지막 방어선:** `UPDATE product SET status='RESERVED' WHERE id=? AND status='ON_SALE'`. 락이 빠져도 2명 당첨은 안 됨
- **커밋 순서와 폴링:** id는 INSERT 때, 화면에 보이는 건 COMMIT 때. 작은 id가 늦게 커밋되면 afterId 폴링이 놓침. 최근 5초를 겹쳐 읽고 프론트가 id로 중복을 거름
- **시계 하나:** DB NOW()와 서버 시각이 섞이면 5분 경계가 흔들림. Clock 주입으로 테스트에서 시간을 멈추고 움직임

## 면접 질문 3개
1. 100명이 같은 상품에 동시에 정확한 댓글을 달면 당첨자가 1명인 걸 어떻게 보장하고 증명했나요? (FOR UPDATE + 조건부 UPDATE, 동시성 테스트 10번 반복, 락을 빼면 실패)
2. 비관적 락 대신 낙관적 락(version)이나 Redis 분산 락을 안 쓴 이유는? (충돌이 아주 잦은 구간이라 낙관적 락은 재시도 폭증, 서버 1대라 분산 락 불필요)
3. afterId 폴링이 댓글을 놓칠 수 있는 이유와 해결 방법은? (id 발급과 커밋 순서가 다름, 겹쳐 읽기)
