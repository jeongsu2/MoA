# 서비스 요구사항 초안 (Phase 0 입력)

> 작성: 2026-10-05, 출처: 정수님 요구사항 메시지 + 첨부 캡처 4장
> 상태: **초안 v4** (2026-10-05 사용자 결정 D-01~D-15 반영, 8장 참고). 서비스명: **MoA (모아)** 나머지 결정 항목은 Phase 1 리서치 항목(R-xx)으로 남겼다.

## 1. 한 줄 정의
인플루언서가 블로그 글 형식으로 중고, 소장품을 올리고, 팔로워가 **댓글로 선착순 구매**하는 플리마켓 웹앱.

## 2. 왜 웹앱인가 (사용자 결정)
인플루언서는 자동 DM이나 프로필 링크로 판매 글을 공유한다. 앱 설치 없이 링크 한 번으로 들어와야 하므로 모바일 웹 우선(Mobile-first Web).

## 3. 현재 방식 (네이버 블로그 캡처에서 관찰한 흐름)
1. 판매자가 글에 상품을 `1-2. 르메메 삭 쁘띠 티사쥬 / 1회착용 / 228,000 -> 140,000` 형태로 나열 (번호 체계: `묶음-순번`)
2. 구매자가 **제품번호를 댓글로** 단다
3. 판매자가 손으로 대댓글 "구매 가능합니다"를 단다
4. 구매자는 **3분 이내** 입금, 시간 초과 시 다음 사람에게 넘어감
5. 입금 후 **비밀 댓글**로 입금자명 / 상품번호 / 입금액(배송비 포함) / 연락처 / 주소 작성
6. 배송비 3,500원, 제주, 산간 6,000원
7. 정해진 기간에 **일괄 발송**, 운송장은 "성함/연락처/운송장번호" 목록으로 글에 일괄 업로드

**이 서비스가 자동화하려는 고통:** 3번(손으로 선착순 판정), 4번(시간 감시와 다음 사람 넘기기), 5번(개인정보가 댓글에 노출될 위험). 7번(운송장)은 현재 범위 밖.

## 4. 기능 요구사항 (사용자 원문 기준)

| ID | 기능 | 사용자 원문 요약 |
|---|---|---|
| F-01 | 회원가입 분리 | 인플루언서(판매자) / 일반 구매자 가입을 따로 |
| F-01a | 가입 시 배송정보 입력 | 가입할 때 **실명**, 전화번호, **기본 배송지**와 추가 배송정보(예: 공동현관 비밀번호, 배송 요청사항)를 입력. 실명은 판매자가 입금자명과 대조하는 데 쓰임 |
| F-01b | 배송지 선택 | 결제(주문) 페이지에서 기본 배송지 또는 새 배송지 중 선택. **기본값은 기본 배송지** |
| F-02 | 글 작성 | 네이버 블로그 글쓰기 같은 간단한 UI (제목 + 본문 + 사진) |
| F-03 | 상품 등록 | 개수 제한 없음. 본문에 `1. 빈티지원피스 2. 보라색에코백` 식 번호로 등록 |
| F-04 | 댓글 주문 | 구매자가 "번호 + 제품명"을 댓글로 작성 |
| F-05 | 선착순 당첨 판정 | 번호와 제품명을 **정확히** 쓴 **첫** 댓글에 ⭐ 당첨 표시. ⭐ 댓글에는 작성자 **실명**이 눈에 띄게 보여 판매자가 입금자명과 바로 대조 가능 |
| F-06 | 입금 시간 제한 | 당첨자는 "입금완료" 댓글로 입금을 신고. **입금완료 신고 시각**이 당첨 후 5분 안이면 통과. 판매자 확인에는 시간 제한 없음 (D-07) |
| F-06b | 판매자 입금확인 버튼 | ⭐ 댓글 아래에 **판매자에게만** 보이는 [입금확인] 버튼. 판매자가 통장 입금을 직접 확인 후 누르면 자동 댓글 "구매감사합니다. 예쁘게 포장해서 전달드릴게요 💓" 작성, 판매 확정 |
| F-06a | 차순위 승계 | 5분 안에 입금이 확인되지 않으면 당첨이 취소되고, 같은 상품을 정확히 기재한 **다음 순서 댓글**에 당첨이 넘어감 (새 5분 시작). 차순위가 없으면 상품은 다시 판매 중이 되고, 이후 첫 정확 댓글이 같은 5분 규칙으로 당첨. 취소된 사람도 같은 상품에 다시 도전 가능 |
| F-04a | 댓글 수정 불가 | 작성한 댓글은 수정할 수 없음. 잘못 썼으면 새 댓글을 달아야 하고, 순서는 새 댓글 시각 기준 |
| F-03a | 상품 수량 | 모든 상품은 **수량 1개** (1점 판매) |
| F-05a | 1인당 구매 제한 | 1인당 최대 **5개** (해석은 D-13 참고) |
| F-01c | 가입 동의 | 가입 시 개인정보 수집, 이용 동의와 판매자에게 배송정보를 제공하는 **제3자 제공 동의**를 체크박스로 받음 |
| F-07 | 결제 | **무통장 입금만** 지원. PG 연동은 현재 범위 밖 |
| ~~F-08~~ | ~~배송 조회~~ | **현재 제외** (운송장 관련 기능 전부) |

## 5. 비기능 요구사항 (가정, ERD에서 수치 확정)
- **순간 동시 접속(버스트):** 판매 글 오픈 직후 수십~수천 명이 같은 상품에 동시에 댓글 → 서비스의 핵심 기술 난제
- **판정 공정성:** "누가 먼저인가"를 서버가 일관되게 판정해야 함 (클라이언트 시각을 믿지 않음)
- **개인정보 보호:** 주소, 연락처는 판매자와 본인에게만 노출
- **모바일 지연:** 링크 진입 후 첫 화면이 빠르게 떠야 함

| D-09 | 차순위 없어도 5분 규칙 동일, 취소자 재도전 허용 | 규칙 일관성, 실수한 구매자에게도 기회 | 차순위 없으면 판매 종료, 취소자 차단 | 같은 사람이 반복 당첨 후 미입금으로 판매를 방해 |

| D-11 | 댓글 수정 불가 | 수정으로 오타를 정답으로 바꿔 순서를 가로채는 문제를 원천 차단, 판정 로직 단순화 (CommentSold와 같은 정책) | 수정 허용 + 수정 시각 기준 재판정 | 오타를 낸 사용자의 불만, 댓글 도배 → 삭제는 허용할지 별도 결정 필요 |
| D-12 | 상품 수량은 항상 1개 | 플리마켓은 1점 판매가 대부분, 재고 차감 로직 없이 "판매중/당첨/판매완료" 상태만으로 표현 | 수량 N개 (공구형) | 같은 상품을 여러 개 팔고 싶은 판매자는 글을 나눠 등록해야 함 |
| D-13 | 1인당 구매 제한 5개 | 한 사람이 여러 상품을 독점하는 것을 막음 | 제한 없음 | ⚠️ 해석 가정: **한 판매 글 안에서** 당첨 중 + 구매 확정 상품 합계 5개. 6번째 정확 댓글은 당첨 대상에서 건너뜀. 동시 댓글 5개가 한꺼번에 들어올 때 6번째가 끼어드는 경쟁 조건 |
| D-14 | 개인정보 수집, 이용 + 제3자 제공 동의를 가입 시 체크박스로 | 개인정보보호법상 판매자(제3자)에게 주소를 넘기려면 동의가 필요. 간단한 체크로 시작 | 주문마다 동의 | 동의 철회 시 진행 중 주문 처리, 약관 문구는 범위 밖 |
| D-15 | 백엔드는 Java + Spring Boot (IntelliJ) | 50명 이상 회사 백엔드 면접에서 가장 많이 쓰고 묻는 스택, 동시성 제어 자료가 많음 ([ADR-002](decisions/ADR-002-backend-language.md)) | Python (FastAPI/Django) | 초반 설정과 코드량이 많아 진도가 느림 |
